# Explanation style — IMPORTANT

Throughout analysis in this project, explain every important research concept at TWO levels.

**Level 1 — Simple / Layman Explanation**: plain language, as if explaining to an intelligent student new to academic research. Simple words, intuitive explanations, concrete examples, analogies, minimal jargon.

**Level 2 — Technical / Research Explanation**: the same idea using proper terminology for the field — formal terminology, methodological details, math/statistics, experimental design, algorithmic details, assumptions, and technical limitations, as relevant.

Use this structure whenever explaining an important research concept (research gaps, novelty, hypotheses, methodology, baselines, ablations, statistical tests, evaluation metrics, data leakage, overfitting, generalization, reproducibility, causality, interpretability, scientific validity, literature findings, reviewer criticisms, publication standards, contributions, limitations, results, future work, etc.):

```
SIMPLE EXPLANATION:
[ordinary language]

TECHNICAL EXPLANATION:
[formal research/technical meaning]

WHY IT MATTERS:
[why this matters for this project or a potential paper]

WHAT WE SHOULD DO:
[the practical action to take]
```

Don't assume technical implementation understanding implies research-methodology understanding — but don't oversimplify to the point of losing important technical detail either. Define a technical term briefly on first use. For hard concepts, build intuition first, then formalize. No jargon for jargon's sake.
